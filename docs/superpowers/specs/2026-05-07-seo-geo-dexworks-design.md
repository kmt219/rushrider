# SEO/GEO Hardening — DexWorks (Approach A)

**Date:** 2026-05-07  
**Branch:** `feat/dynamic-page-titles` (extends existing PR #232)  
**Scope:** `apps/dexworks` only

---

## Problem

The dexworks app is a client-side React SPA. After PR #232 added dynamic `document.title` and OG/Twitter meta descriptions per route, five gaps remain:

1. `og:url` and `link[rel="canonical"]` never update from the root URL — every page looks like a duplicate of `https://dex.goldrush.dev` to crawlers.
2. No `og:image` / `twitter:image` — social link previews are blank cards.
3. No JSON-LD structured data — search engines and AI crawlers cannot understand the app's entities or page hierarchy.
4. No `robots.txt` — `/api/` endpoints are crawlable and bots have no sitemap pointer.
5. No `sitemap.xml` — known stable routes are invisible to search engines.

---

## Component Designs

### 1. `src/lib/pageMeta.ts` — updated API

```typescript
export function setPageMeta(
  title: string,
  description: string,
  opts?: {
    path?: string;          // "/base/lp?pool=0x..." — sets canonical + og:url
    jsonLd?: object;        // injected as <script id="ld-json-page" type="application/ld+json">
  }
): void

export function resetPageMeta(): void  // called on unmount — restores root defaults + removes JSON-LD
```

**Behaviour:**
- `og:url` and `link[rel="canonical"]` → `https://dex.goldrush.dev${path}` (or `window.location.pathname + search` if `path` omitted)
- JSON-LD → upserts a single `<script id="ld-json-page">` tag in `<head>`; `resetPageMeta` removes it
- All existing meta fields (title, description, og:title, twitter:*) unchanged

### 2. JSON-LD schemas per route

**`index.html` (static, bot-visible before JS runs):**
```json
{
  "@context": "https://schema.org",
  "@type": "WebApplication",
  "name": "GoldRush DEX",
  "url": "https://dex.goldrush.dev",
  "applicationCategory": "FinanceApplication",
  "description": "Real-time DEX pair discovery, OHLCV charting, and LP analytics.",
  "provider": { "@type": "Organization", "name": "Covalent", "url": "https://www.covalenthq.com" },
  "offers": { "@type": "Offer", "price": "0", "priceCurrency": "USD" }
}
```

**`/:chainName` (App.tsx) — updates on chain change:**
```json
{
  "@type": "WebPage",
  "name": "{Chain} Live DEX Activity — GoldRush DEX",
  "breadcrumb": { "itemListElement": [
    { "position": 1, "name": "GoldRush DEX", "item": "https://dex.goldrush.dev" },
    { "position": 2, "name": "{Chain}", "item": "https://dex.goldrush.dev/{chainSlug}" }
  ]}
}
```

**`/:chainName/lp` (LPDashboard.tsx) — updates when pool data loads:**
```json
{
  "@type": "WebPage",
  "name": "{TOKEN0}/{TOKEN1} LP on {Chain} — GoldRush DEX",
  "breadcrumb": { "itemListElement": [
    { "position": 1, "name": "GoldRush DEX", "item": "https://dex.goldrush.dev" },
    { "position": 2, "name": "{Chain}", "item": "https://dex.goldrush.dev/{chainSlug}" },
    { "position": 3, "name": "LP Explorer", "item": "https://dex.goldrush.dev/{chainSlug}/lp" }
  ]}
}
```

**`/:chainName/compare` (DexCompare.tsx):**
```json
{
  "@type": "WebPage",
  "name": "DEX Pair Compare — {Chain} | GoldRush DEX",
  "breadcrumb": { "itemListElement": [
    { "position": 1, "name": "GoldRush DEX", "item": "https://dex.goldrush.dev" },
    { "position": 2, "name": "{Chain}", "item": "https://dex.goldrush.dev/{chainSlug}" },
    { "position": 3, "name": "Compare", "item": "https://dex.goldrush.dev/{chainSlug}/compare" }
  ]}
}
```

All dynamic JSON-LD schemas include `"@context": "https://schema.org"` and `"url"` field matching the canonical.

### 3. OG image — `public/og-image.png` (1200×630)

Generated by `scripts/gen-og-image.mjs` at build time using `@resvg/resvg-js`.

**Visual design** (matches app's dark brutalist aesthetic):
- Background: `#0b0b0b`
- Left 55%: "GOLDRUSH" small green label → "DEX" large white → feature bullets → chain badges (BASE · MEGAETH · BNB · MONAD)
- Right 45%: simplified pair table mockup (3 rows, green accent on selected row, PRICE + SAFE columns)
- Bottom bar: "POWERED BY GOLDRUSH · dex.goldrush.dev"
- Accent colour: `#00cc66`; muted: `#555`; border lines: `#1e1e1e`
- Font: embedded JetBrains Mono subset via base64 (keeps script self-contained)

Script is idempotent — safe to re-run. Added as `package.json` script: `"gen-og": "node scripts/gen-og-image.mjs"`.

`index.html` gets:
```html
<meta property="og:image" content="https://dex.goldrush.dev/og-image.png" />
<meta name="twitter:image" content="https://dex.goldrush.dev/og-image.png" />
```

Covers known stable routes only. Dynamic `/:chainName/:pairAddress` omitted (infinite space).

Chains: `base`, `megaeth`, `bnb`, `monad`  
Priorities: chain home 1.0/0.9, `/lp` 0.8, `/compare` 0.7  
`changefreq`: chain homes `always`; lp/compare `daily`  
`lastmod`: set to spec date `2026-05-07`

## What This Does NOT Do

- **SSR / pre-rendering** — OG tags still require JS for per-route values; static OG image is the mitigation for bots that skip JS
- **Dynamic OG images per pair/pool** — deferred to a follow-up PR using `@vercel/og`
- **`og:image` for LP/compare routes** — all routes share `og-image.png`; route-specific images need server-side generation
